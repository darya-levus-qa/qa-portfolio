# Сценарии из юнитов

Сценарий - цепочка запросов, где каждый шаг использует данные предыдущего. Токен для подключения берется из файла аккаунтов, Id созданных сущностей передаются между шагами через переменные. Созданные в сценарии данные удаляются в конце, поэтому сценарий можно запускать повторно без ручной подготовки.

## Сценарий 1. Вывести определенную задачу сотрудника из плана на день

| Шаг | Действие |
|---|---|
| 1 | Подключение к API с токеном пользователя |
| 2 | Получение списка сотрудников с поиском по фамилии |
| 3 | Получение списка задач сотрудника из плана на день |
| 4 | Получение детальной информации задачи из плана на день |

Проверки на шаге 2: IsSuccess = true, Id найденного сотрудника, количество найденных записей = 1.

## Сценарий 2. Построить простую карту связей между задачами

| Шаг | Действие |
|---|---|
| 1 | Подключение к API с токеном пользователя |
| 2 | Создание задачи |
| 3 | Создание подзадачи 1 |
| 4 | Создание подзадачи 2 |
| 5 | Получение диаграммы связей задачи |
| 6-8 | Удаление созданных задач |

Проверки при создании задачи: IsSuccess = true, ErrorMessage = null, название созданной задачи. Id созданной задачи сохраняется в переменную и используется в следующих шагах.

## Сценарий 3. Назначить шеринговую задачу сотруднику в план на день

| Шаг | Действие |
|---|---|
| 1 | Подключение к API с токеном пользователя |
| 2 | Создание задачи |
| 3 | Обновление статуса задачи |
| 4 | Получение рабочего пространства по Id |
| 5 | Добавление исполнителя |
| 6 | Добавление задачи в план на день |
| 7 | Получение плана на день пользователей |
| 8 | Удаление задачи |

Id созданной задачи сохраняется в переменную и передается в шаги 3-8.
