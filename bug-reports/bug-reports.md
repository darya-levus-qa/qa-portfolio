# Баг-репорты

Примеры из коммерческой работы на проекте Hub-PM. Все данные обезличены: email, имена, Id, домены и внутренние названия заменены на условные.

## Пример 1. Несоответствие макету: шрифт заголовков на мобильной версии

**Заголовок:** Настройки профиля: насыщенность шрифта и высота строки заголовков блоков "Основное", "Почта", "Действия" на мобильной версии сайта не соответствуют макету

**Предусловия**

1. Пользователь авторизован
2. Сайт открыт на мобильной версии

**Описание**

Шрифт заголовков блоков на странице "Настройки профиля" (мобильная версия, раздел "Основные", заголовки блоков "Основное", "Почта", "Действия") не соответствует макету:

на макете - насыщенность шрифта 400 (Roboto Regular), высота строки 24px

на мобильной версии сайта - насыщенность шрифта 500 (Roboto Medium), высота строки 20px

**Шаги воспроизведения**

1. Открыть сайт на мобильной версии
2. Открыть страницу "Настройки профиля"
3. Выбрать раздел "Основные"
4. Открыть DevTools, выбрать заголовок блока "Почта" и посмотреть вкладку "Computed"

**Фактический результат**

Насыщенность шрифта заголовков блоков - 500 (Roboto Medium), высота строки - 20px

**Ожидаемый результат**

Насыщенность шрифта заголовков блоков - 400 (Roboto Regular), высота строки - 24px, согласно макету

**Приложения:** скриншот стилей макета, скриншот вкладки "Computed" в DevTools, ссылка на макет

## Пример 2. Несоответствие макету: несколько отличий одного элемента

**Заголовок:** Настройки профиля: размер, текст и рамка плашки подтверждения выхода в разделе "Выйти из профиля" не соответствуют макету

**Предусловия**

1. Пользователь авторизован

**Описание**

Плашка подтверждения выхода на странице "Настройки профиля" (раздел "Выйти из профиля", плашка с кнопками "Остаться" и "Выйти" под заголовком раздела) не соответствует макету:

на макете - размер плашки 490x110px

на макете - текст плашки "Выберите действие"

на макете - рамка плашки со всех сторон

на десктопной версии сайта - размер плашки 1564x104px

на десктопной версии сайта - текст плашки "Вы уверены, что хотите выйти из профиля?"

на десктопной версии сайта - рамка плашки только с левой стороны

**Шаги воспроизведения**

1. Открыть страницу "Настройки профиля"
2. Выбрать в левой панели раздел "Выйти из профиля"
3. Посмотреть на плашку с кнопками "Остаться" и "Выйти"

**Фактический результат**

Размер плашки - 1564x104px, текст плашки - "Вы уверены, что хотите выйти из профиля?", рамка только с левой стороны

**Ожидаемый результат**

Размер плашки - 490x110px, текст плашки - "Выберите действие", рамка со всех сторон, согласно макету

**Приложения:** скриншот макета, скриншот десктопной версии сайта, ссылка на макет

## Пример 3. API: ошибка 500 вместо ошибки валидации

**Заголовок:** Main Ws / EmployeeService / UpdateEmployeeForManager - при несуществующем UserId возвращается ошибка 500 вместо ошибки валидации

**Предусловия**

1. Пользователь авторизован в системе
2. Есть сотрудник в рабочей области

**Описание**

При отправке запроса на метод Main Ws / EmployeeService / UpdateEmployeeForManager с несуществующим значением в поле UserId метод не проверяет существование пользователя и падает на уровне базы данных - возвращается код 500 и текст исключения DbUpdateException с нарушением внешнего ключа. Для остальных некорректных значений поля (0, отрицательное, дробное, максимум и минимум Int64, пустое, Null) метод возвращает корректную ошибку валидации.

**Шаги воспроизведения**

1. Отправить запрос на метод Main Ws / EmployeeService / UpdateEmployeeForManager, указав в поле UserId несуществующий Id

**Фактический результат**

Возвращается ошибка с кодом 500 и текстом исключения базы данных DbUpdateException

**Ожидаемый результат**

Метод Main Ws / EmployeeService / UpdateEmployeeForManager возвращает ошибку валидации

**Приложения:** аккаунт, под которым воспроизводится

## Пример 4. API: поле принимает значения вне перечисления

**Заголовок:** Main Ws / PerformersListService / GetOwnedDetailUsers - поле Role принимает значения вне перечисления ProjectPerformerRole

**Предусловия**

1. Пользователь авторизован в системе
2. Есть проект с сотрудниками

**Описание**

Поле Role принимает значения, которых нет в перечислении ProjectPerformerRole (в нем только 0 - Employee, 1 - NamespaceAdmin, 2 - ProjectAdmin). Вместо ошибки валидации возвращается успешный ответ со списком сотрудников, переданное значение игнорируется:

1. Role = 3 (значение вне перечисления) - успешный ответ со списком сотрудников
2. Role = -1 (отрицательное значение) - успешный ответ со списком сотрудников

**Шаги воспроизведения**

1. Отправить запрос на метод Main Ws / PerformersListService / GetOwnedDetailUsers, указав в поле Role значение 3
2. Отправить запрос на тот же метод, указав в поле Role значение -1

**Фактический результат**

В обоих случаях возвращается "IsSuccess": true и список сотрудников

**Ожидаемый результат**

Метод Main Ws / PerformersListService / GetOwnedDetailUsers возвращает ошибку валидации

**Приложения:** аккаунт, под которым воспроизводится, ответы на оба запроса
