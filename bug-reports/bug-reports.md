# Баг-репорты

Примеры из коммерческой работы на проекте Hub-PM (WebSocket API). Все данные обезличены.

## Пример 1. Функциональный баг: фильтр по роли не применяется

**Заголовок:** Метод получения списка сотрудников владельца - фильтр по роли не применяется для ролей "Сотрудник" и "Администратор рабочей области"

**Предусловия**

1. Пользователь авторизован под владельцем
2. Есть проект с сотрудниками
3. В проекте есть администратор проекта и сотрудник без прав администратора

**Описание**

При отправке запроса на метод получения списка сотрудников владельца фильтр по роли работает только для роли "Администратор проекта": у пользователя, который не является администратором проекта, список проектов приходит пустым. Для ролей "Сотрудник" и "Администратор рабочей области" фильтр не применяется:

1. Фильтр "Сотрудник", в поиске администратор проекта - проект возвращается, хотя пользователь не обычный сотрудник
2. Фильтр "Администратор рабочей области", в поиске сотрудник без прав администратора рабочей области - проект возвращается
3. Фильтр "Администратор проекта", в поиске сотрудник без прав администратора проекта - список проектов пустой, фильтр работает

**Шаги воспроизведения**

1. Отправить запрос на метод с фильтром по роли "Сотрудник" и поиском по фамилии администратора проекта
2. Отправить запрос на метод с фильтром по роли "Администратор рабочей области" и поиском по фамилии сотрудника без прав администратора рабочей области
3. Отправить запрос на метод с фильтром по роли "Администратор проекта" и поиском по фамилии сотрудника без прав администратора проекта

**Фактический результат**

После запросов с фильтрами "Сотрудник" и "Администратор рабочей области" проект возвращается у пользователей, которые не соответствуют роли. После запроса с фильтром "Администратор проекта" список проектов пустой.

**Ожидаемый результат**

Метод возвращает только проекты, в которых пользователь имеет выбранную роль, для всех ролей

**Приложения:** аккаунт, под которым воспроизводится, ответы на все три запроса

## Пример 2. Ошибка метода: 500 вместо ошибки валидации

**Заголовок:** Метод привязки сотрудников к руководителю - при несуществующем пользователе возвращается ошибка 500 вместо ошибки валидации

**Предусловия**

1. Пользователь авторизован в системе
2. Есть сотрудник в рабочей области

**Описание**

При отправке запроса на метод привязки сотрудников к руководителю с несуществующим Id руководителя метод не проверяет существование пользователя и падает на уровне базы данных - возвращается ошибка 500 с текстом исключения базы данных. Для остальных некорректных значений (0, отрицательное, дробное, максимальное и минимальное число, пустое значение, Null) метод возвращает корректную ошибку валидации.

**Шаги воспроизведения**

1. Отправить запрос на метод привязки сотрудников к руководителю, указав несуществующий Id руководителя

**Фактический результат**

Возвращается ошибка 500 с текстом исключения базы данных

**Ожидаемый результат**

Метод возвращает ошибку валидации

**Приложения:** аккаунт, под которым воспроизводится

## Пример 3. Права доступа: пользователь без доступа получает данные рабочей области

**Заголовок:** Методы получения приоритетов рабочей области - пользователь без доступа к рабочей области получает ее приоритеты

**Предусловия**

1. Пользователь авторизован
2. Пользователь не является участником проекта и рабочей области
3. В рабочей области настроены приоритеты

**Описание**

Методы получения списка приоритетов и детальной информации по приоритетам возвращают приоритеты рабочей области пользователю, у которого нет доступа к этой рабочей области. Проверка доступа к рабочей области в методах не работает:

1. Получение списка приоритетов под пользователем без доступа - успешный ответ, приоритеты возвращаются
2. Получение детальной информации по приоритетам под пользователем без доступа - успешный ответ, приоритеты возвращаются

**Шаги воспроизведения**

1. Отправить запрос на получение списка приоритетов рабочей области под пользователем без доступа
2. Отправить запрос на получение детальной информации по приоритетам той же рабочей области под тем же пользователем

**Фактический результат**

Оба метода возвращают успешный ответ и приоритеты рабочей области

**Ожидаемый результат**

Оба метода возвращают ошибку доступа, приоритеты не возвращаются

**Приложения:** аккаунт пользователя без доступа, ответы обоих методов
